## 최초 단일 스테이지 기록

Unity 6000.6.5f1 / Android portrait / uGUI / Input System.

Open `Assets/ColorMovePuzzle/Scenes/ColorMovePuzzle.unity` and press Play. The scene is also the first enabled scene in Build Settings. No Inspector setup is needed.

## Controls and rules

- Tap a tile when exactly one orthogonal adjacent cell is empty.
- If two or more destinations are empty, swipe toward the intended destination. A drag must cover at least 12% of a tile width. Nearly diagonal gestures are ignored.
- Moves slide for 0.15 seconds with smoothstep interpolation. Inputs are locked during the slide; successful moves increment the counter once.
- Restart restores the original board and zero moves, including when pressed during a slide.
- Matching all nine colors/empty positions opens the clear overlay, shows the move total, and locks further moves. Play Again restarts the stage.
- Tile letters R/B/Y/K supplement color. Empty cells have no interactive tile.

Stage target and fixed start, in row-major order:

```text
TARGET      START
R R B       R B R
B Y Y       B Y E
K E E       E K Y
```

`Stage01.asset` stores the target and 24 legal scramble moves. Start is generated by applying those moves to the target. The inverse record supplies a verified solution for tests; it is not exposed as an in-game hint or solver. Same-color tiles and empty cells have no identities.

## Code

All game source is under `Assets/ColorMovePuzzle/`.

| Script | Responsibility |
| --- | --- |
| `Core/PuzzleBoard.cs` | Pure C# cells, color/move types, adjacency validation, copying, matching |
| `Runtime/PuzzleStageData.cs` | ScriptableObject stage data, legal scramble generation and inverse record |
| `Runtime/PuzzlePalette.cs` | Tile colors and accessibility letters |
| `Runtime/PuzzleTileView.cs` | Pointer/touch capture, tap/drag events, smooth slide rendering |
| `Runtime/PuzzleBoardView.cs` | Data-to-UI binding and grid coordinates |
| `Runtime/PuzzleGameController.cs` | Input gating, counter, restart and completion |
| `Runtime/PuzzleScreenLayout.cs` | Safe-area fitting and uniform content scaling |
| `Editor/PuzzleSceneBuilder.cs` | Reproducible live-editor construction, asset/reference wiring, portrait settings |
| `Tests/EditMode/PuzzleBoardTests.cs` | Independent model and stage tests |
| `Tests/PlayMode/PuzzlePlayTests.cs` | Actual scene, raycast, gestures, animation, restart, completion tests |

The Core assembly disables Unity engine references. The board size is data driven; the view and builder use that size when calculating cells. Only the requested 3×3 stage is authored. Each MonoBehaviour has its own matching filename. Test and editor assemblies are excluded from release players.

`AgentScripts/` contains local CLI verification/authoring scripts outside Assets, so they do not ship with the game. The scene builder refuses to overwrite an existing game scene or discard dirty scenes. It can be invoked through Pipeline `script eval_file` using `AgentScripts/BuildScene.cs` in a fresh checkout before that scene exists.

## Saved scene

```text
UICamera                         (orthographic; no 3D scene renderers)
PuzzleCanvas                     (Overlay, CanvasScaler 1080×1920, GraphicRaycaster)
  Background
  SafeArea
    Content                      (1080×1920, uniformly fitted)
      Header                     (stage, moves, title)
      TargetArea
        TargetGrid
          Cells                  (9 noninteractive Image slots)
          Tiles                  (7 noninteractive Image tiles)
      PuzzleArea
        CurrentBoard
          Cells                  (9 noninteractive Image slots)
          Tiles                  (7 interactive Image tiles)
      Footer                     (instructions, RestartButton)
  ClearOverlay                   (inactive until completed)
    ClearSafeArea / ClearContent (message, total, PlayAgainButton)
PuzzleGame                       (controller with serialized references)
EventSystem                      (InputSystemUIInputModule)
```

UI uses rounded, sliced Image sprites and TextMeshPro. Cell positions are computed directly because a GridLayoutGroup would override sliding tile positions. The game scene contains no MeshFilter, MeshRenderer, Collider, Rigidbody or 3D primitive. The pre-existing SampleScene/TestCube and other original assets were preserved.

Portrait orientation and 1080×1920 default dimensions were set through PlayerSettings. Existing build scenes were retained after inserting the puzzle scene first. TMP Essentials were imported noninteractively for fonts; no additional package was installed.
