# ColorMovePuzzle — 30 스테이지 시스템

3차 개발에서 시작 화면은 메인 메뉴로 변경했습니다. 아래의 스테이지 시스템은 유지되며 메인 메뉴에서 3×3을 선택하면 열립니다. 최신 화면 전환/이어하기/설정은 [README-MainMenu.md](README-MainMenu.md)를 참고하십시오.

`Assets/ColorMovePuzzle/Scenes/ColorMovePuzzle.unity`를 열고 Play를 누르면 스테이지 선택 화면으로 시작합니다. 처음에는 1번만 선택할 수 있습니다. GameObject 생성이나 Inspector 설정은 필요 없습니다.

## 구현한 흐름

- 3열 × 10행, 총 30개 카드가 있는 세로 ScrollRect 화면.
- 잠긴 스테이지는 자물쇠 아이콘과 LOCKED 표시. 버튼을 눌러도 진입할 수 없습니다.
- 다음 도전 스테이지는 밝은 배경과 NEXT 표시, 클리어한 스테이지는 체크 아이콘과 COMPLETE 표시.
- 카드는 스테이지 번호와 정확한 최소 이동 횟수를 표시합니다.
- 클리어 즉시 다음 스테이지를 해금하고 진행을 저장합니다. 이전 스테이지를 다시 풀어도 해금 상태는 유지됩니다.
- 퍼즐 상단 STAGES 버튼으로 선택 화면에 돌아갈 수 있습니다. 이동 애니메이션 중 돌아가면 진행 중인 애니메이션을 취소하고, 다시 입장할 때 최초 배치로 시작합니다.
- 클리어 화면에는 NEXT STAGE, PLAY AGAIN, STAGE SELECT가 있습니다. 마지막 스테이지에는 다음 버튼이 없으며 전체 완료 메시지가 표시됩니다.
- 기존 탭/방향 스와이프, 0.15초 애니메이션, 입력 잠금, 이동 횟수와 재시작 동작을 유지합니다.

## 난이도와 BFS

`PuzzleDifficultyCalculator`는 **Editor 전용 어셈블리**에 있습니다. 목표에서 역방향 BFS를 수행하여 모든 도달 가능한 색상 배치의 최소 거리를 계산합니다. 플레이어 빌드에는 BFS 코드와 전체 거리표가 들어가지 않습니다.

각 칸의 색상값을 3비트로 저장하는 27비트 키를 사용합니다. 타일별 ID를 저장하지 않아 같은 색상과 두 빈칸은 자동으로 동일하게 취급됩니다. 빈칸에 인접한 색상 타일을 한 칸 이동한 상태만 이웃으로 생성합니다. 이동은 가역적이므로 목표에서 계산한 거리가 시작에서 목표까지의 정확한 최소 이동 횟수입니다.

고정 목표:

```text
R R B
B Y Y
K E E
```

전체 도달 상태는 **22,680개**입니다. 이는 `9! / (2! × 2! × 2! × 2!)`와 같으며 이 색상 구성의 모든 서로 다른 배치를 포함합니다. 최대 최소 거리는 **20회**입니다.

30개 스테이지의 최소 이동 횟수:

```text
01–10:  2, 2, 3, 3, 4, 5, 5, 6, 6, 7
11–20:  8, 8, 9,10,10,11,11,12,13,13
21–30: 14,15,15,16,16,17,18,18,19,20
```

거리는 감소하지 않게 배치했습니다. 같은 거리에서는 기존에 선택한 배치와의 색상 차이, 빈칸 조합의 사용 횟수, 검은 타일 위치의 사용 횟수를 고려하여 결정적으로 선택합니다. 최종 30개 시작 배치는 중복이 없고 목표와 다릅니다. 빈칸 위치 조합은 **29종**, 검은 타일 위치는 **9칸 전체**를 사용합니다.

각 스테이지 에셋에 보드 크기, 시작 배치, 개별 목표 배치, 최소 이동 횟수와 검증용 최단 풀이가 저장됩니다. 현재 목표는 고정이지만 스테이지마다 다른 목표를 지정할 수 있습니다. 보드 크기도 데이터 필드로 유지하며 4×4/5×5 스테이지는 추가하지 않았습니다.

`Artifacts/StageSystem/Stages.csv`에는 30개 시작·목표 배치와 최소 거리가, `BfsSummary.json`에는 전체 거리 분포가 기록되어 있습니다.

## 로컬 저장

저장 경로는 `Application.persistentDataPath/ColorMovePuzzle/progress-v1.json`입니다. 기기별 Unity persistentDataPath 아래에 저장되며 앱 재실행 시 읽습니다.

- 버전, 클리어한 스테이지 번호 목록, 마지막 선택 스테이지를 기록합니다.
- 해금 수는 저장값을 직접 믿지 않고 연속된 클리어 기록으로 계산합니다.
- 클리어 시 즉시 저장하므로 앱 종료 콜백에 의존하지 않습니다.
- 임시 파일 작성 후 교체하고 직전 정상 파일을 `.bak`으로 보관합니다. 플랫폼에서 원자적 교체를 지원하지 않으면 백업 후 복사합니다.
- 잘못된 JSON이나 지원하지 않는 버전은 백업을 시도하고, 정상 데이터가 없으면 1번만 열린 상태로 복구합니다.
- 저장 실패가 발생하면 선택 화면에 저장 공간 확인 안내를 표시합니다.
- 진행 중인 퍼즐의 칸 위치/이동 횟수는 저장하지 않습니다. 스테이지 재입장은 최초 배치로 시작합니다.

자동 테스트는 임시 경로의 별도 저장 파일을 사용하므로 사용자 해금 기록을 변경하지 않습니다.

## 씬 구조

기존 PuzzleCanvas와 퍼즐 격자는 유지했습니다. Canvas의 새 StageSelection 아래에 안전 영역과 기준 해상도 콘텐츠를 두고, StageScrollView → Viewport(Image + Mask) → StageRows(VerticalLayoutGroup + ContentSizeFitter) → 10개 행(HorizontalLayoutGroup) → 30개 카드를 생성했습니다. ScrollRect와 Scrollbar 참조, 카드 버튼 콜백, STAGES/다음 단계/선택 화면 버튼을 연결했습니다. 잠금과 체크 아이콘은 uGUI Image 스프라이트입니다.

## 자동 검증 기준

- BFS가 22,680개 상태를 빠짐없이 포함하는지 확인합니다.
- 모든 이웃 간 거리 차가 1 이하인지, 0 이외의 상태에서 거리가 1 감소하는 이웃이 있는지 기존 PuzzleBoard 규칙으로 독립 검증합니다. 유일한 거리 0이 목표임을 함께 확인하면 최단 거리의 상·하한을 모두 인증할 수 있습니다.
- 30개 시작 배치의 중복/목표 동일 여부, 저장된 거리, 실제 합법적 풀이 길이, 난이도 순서와 다양성을 검증합니다.
- 새로운 목표를 넣었을 때도 해당 목표가 거리 0이 되는지 확인합니다.
- 초기 잠금, 다음 단계 해금, 재플레이, 최종 단계, 파일 왕복/손상/백업 복구를 검증합니다.
- 기존 보드·입력·애니메이션·재시작·클리어 테스트를 유지합니다.
- PlayMode에서 1~30번을 실제 애니메이션과 NEXT STAGE 버튼으로 연속 클리어하고, 저장/최종 완료 표시를 검사합니다.

최종 실행 결과: **EditMode 33개 통과 / 실패 0**, **PlayMode 13개 통과 / 실패 0**. 30단계 연속 클리어 검증도 실제 실행하여 통과했습니다. 전체 PlayMode 실행 시간은 약 57초였습니다. 보고서는 `Artifacts/StageSystem/`에 저장했습니다.

추가로 가상 Touchscreen을 실제 InputSystem에 연결해 카드 터치, 다음 단계 버튼, 선택 화면 복귀와 드래그 스크롤을 확인했습니다. 새 레이아웃 및 입력 장치 준비를 두 프레임 기다린 뒤 모두 통과했습니다. 미리보기는 별도 저장 파일을 사용했으며 사용자 진행 파일은 변경하지 않았습니다.

초기 저장 손상/지원 버전 테스트에서 발견된 예외 처리 누락은 수정한 뒤 재검증했습니다. 테스트 중 한 차례 에디터 처리 지연으로 씬 조회가 시간 초과되었으나, 이후 처리 재개와 전체 테스트 완료를 확인했습니다. 자동으로 Unity에 로그를 전송하지 않았습니다.

Android APK/AAB 빌드와 실기기 검증은 이 작업에 포함하지 않았습니다.
